## Recepción real en Prometheus

La salida del proceso indica `Prometheus remote write (http://prometheus:9090/api/v1/write)`.
No se encontraron errores de envío en el log. La verificación posterior devuelve **14 comprobaciones en true**:

| Serie | Series / muestras originales almacenadas | Evidencia |
|---|---|---|
| `k6_http_reqs_total` | 1 / 8 | Último contador: 8 |
| `k6_vus` | 1 / 9 | Máximo observado: 1 |
| `k6_http_req_duration_seconds` | 1 / 8 | Muestras de tipo histograma nativo; count final: 8 |

Todas contienen testid correcto, `load_scenario=integration_smoke`, `measurement_kind=integration_smoke`
y `product_replicas=1`. El HTTP lleva `phase=smoke`, `name=catalogue_smoke`, `method=GET`, escenario
interno `integration` y respuesta esperada. No aparecen etiquetas URL, user_id, order_id, request_id, vu,
iter, token ni password en las tres series verificadas.

Comprobación empírica de unidades:

```text
sum nativo final = 0.048869465 segundos
count nativo final = 8
0.048869465 / 8 × 1000 = 6.108683125 ms
media del JSON k6       = 6.108683125 ms
```

La coincidencia verifica la conversión segundos → milisegundos. El API devuelve el campo `histograms`,
con count/sum/buckets reales; no es un gauge de p95 ni un histograma fabricado desde el resumen.

Tras finalizar, las consultas instantáneas de las tres series quedaron vacías por stale markers.
Sus muestras históricas permanecen consultables. Esto evita presentar el VU anterior como actividad actual.

## Registro de comandos ejecutados

**Registro de la única prueba ya realizada. No volver a ejecutar esta carga sin nueva autorización.**

```powershell
$id = 'smoke-20261024-182248-102af0fe2d824714b7e7b6d59eebc964'
docker compose --project-name uce-k6-smoke `
  --env-file tests/demo/observability/compose.vars `
  --project-directory tests/demo/observability `
  -f tests/demo/observability/compose.k6-smoke.yaml run --rm --no-deps `
  -e "RUN_ID=$id" `
  -e K6_PROMETHEUS_RW_SERVER_URL=http://prometheus:9090/api/v1/write `
  -e K6_PROMETHEUS_RW_TREND_AS_NATIVE_HISTOGRAM=true `
  -e K6_PROMETHEUS_RW_PUSH_INTERVAL=5s `
  -e K6_PROMETHEUS_RW_STALE_MARKERS=true `
  k6-smoke run --out experimental-prometheus-rw `
  --system-tags status,method,name,group,check,error_code,scenario,expected_response `
  --tag "testid=$id" --tag load_scenario=integration_smoke `
  --tag product_replicas=1 --tag measurement_kind=integration_smoke `
  /scripts/smoke_prometheus.js
```

La invocación se capturó con Tee-Object al log del mismo id; su vector exacto de argumentos y código de
salida están en el contexto `-env.json`. La protección `execution_started` impidió repetir esa ejecución.
Otros comandos fueron exclusivamente de lectura o captura:

```powershell

backend\order-service\.venv\Scripts\python.exe -B tests/demo/observability/capture_smoke.py $id --replicas 1
```

También se consultaron `docker ps`, inspecciones de metadatos seleccionados, `docker logs` filtrado por
X-Request-ID, configuración Compose con env vacío y APIs de consulta Grafana/Prometheus. No se ejecutó
otra invocación k6, ni se repitieron pruebas para mejorar las imágenes.
